## New requirement — per-memory model stamp (attestation) for the cross-tier ladder (2026-07-10)

**Status: CANONIZED 2026-07-23 (D-PRODUCER-MODEL-PROVENANCE + D-CAPABILITY-ELIGIBILITY + D-CAPABILITY-REGISTRY) · IMPLEMENTATION UNBUILT.** (Walter-specified.) To support the **step-down / cross-tier ladder** — where memories produced by higher-capability models are injected into sessions running lower-tier models — each memory must carry an **attested stamp of which model produced it**, so the client (through the hub) can filter/rank candidates by tier. The stamp is therefore an **attestation requirement**, not merely a label: it is what lets a lower-tier session safely inherit a higher-tier memory.

The tiering is gated by the **Artificial-Analysis Intelligence Index v4.1 gap-ladder**: adjacent-tier gaps of roughly **~4.4 → 6.0 → 7.0** index points, with **no gap-skipping** — an absent middle rung blocks injecting the next tier up (you may only step across an adjacent gap, never leap over a missing rung).

**SUPERSEDED (2026-07-23):** gap thresholds are now re-derived from the pinned AA-II v4.1 capability-registry snapshot per D-CAPABILITY-REGISTRY (tier + uncertainty-band, versioned), not fixed magic numbers.

**Currently unbuilt:** there is **no per-memory model stamp on the chain commitment**, and the **AA-Index gap-ladder is not yet in canon**. This is the enabling requirement for cross-compatible-LLM memory reuse.

**Canonization note (2026-07-23):** the canon gap referenced above is now closed by D-PRODUCER-MODEL-PROVENANCE, D-CAPABILITY-ELIGIBILITY, and D-CAPABILITY-REGISTRY; implementation remains unbuilt.

## New requirement — provenance SERVING gate + witnessed pathways + trajectory/extraction welds (2026-07-23)

- **Serving gate** — a distinct admission gate (separate from moderation/receipt/contribution) that refuses to SERVE inadmissible provenance; commit ≠ serveable.
- **Two admissible pathways** — P1 `ATTESTED_EXECUTION` (open-weight; CommitLLM-class local verifiable execution is a recorded pre-integration spike) and P2 `PROVIDER_WITNESSED` (blind-witness TLS/transport commitment; hub = initial witness; witness routing UNBUILT).

- **Extraction-leg provenance + welds** — bind (a) producer-evidence→substrate, (b) substrate/chunk-plan→every extraction request, (c) extraction-responses→submitted memory. Extraction is post-hoc, user-triggered, multi-call; NOT a WeVibe-controlled single call — UNBUILT.
